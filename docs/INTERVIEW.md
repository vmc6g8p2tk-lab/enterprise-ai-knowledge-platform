# Project interview questions

These answers describe the implemented local prototype. They do not imply production capacity or a security certification. Paths are relative to the repository root.

1. **Why separate Go and Python?** Short: Go owns authentication, RBAC, metadata and jobs; Python owns parsing and model inference. Deep: The boundary lets each service use suitable libraries but adds network failure and latency, so internal calls have an independent token and bounded timeouts. Code: `backend/internal/httpapi/api.go`, `ai-service/app/main.py`, `ARCHITECTURE.md`.
2. **Why PostgreSQL and pgvector?** Short: Business rows and small-scale vectors can live in one transactional database. Deep: KB filtering, document foreign keys and exact cosine search are easy to reason about; large-corpus ANN and database contention have not been measured. Code: `backend/migrations/`, `ai-service/app/rag.py`.
3. **Why BGE-M3?** Short: It is a real multilingual embedding model that ran locally with 1024-dimensional vectors. Deep: This avoids a paid API in the local test, but quality is established only on the committed 20+4 synthetic set, not arbitrary enterprise documents. Evidence: `docs/LOCAL_MODELS.md`, `docs/RAG_EVALUATION.md`.
4. **How are chunks made?** Short: Prefer paragraph and sentence boundaries, enforce a character cap and overlap adjacent chunks. Deep: Overlap keeps cross-boundary facts but creates duplicate evidence and may induce extra citations. Code: `ai-service/app/chunking.py`, `docs/RAG_DESIGN.md`.
5. **Why not split every fixed N characters?** Short: It can break a fact mid-sentence. Deep: Boundary-aware splitting makes each returned passage easier to interpret, though it still does not model semantic topics or actual token counts. Code: `ai-service/app/chunking.py`.
6. **How was Top-K chosen?** Short: The local profile retrieves 8 and reranks to 4. Deep: The setting was tested on a small fixed corpus and should be re-evaluated with harder questions; a perfect fixture Hit@8 is not proof that 8 is globally optimal. Code: `ai-service/app/rag.py`, `docs/RAG_EVALUATION.md`.
7. **Why rerank after vector search?** Short: Vector search provides candidates; reranking orders the smaller set. Deep: The current lexical reranker is cheap and transparent but can miss paraphrases. A learned cross-encoder would add latency and require its own evaluation. Code: `ai-service/app/reranking.py`.
8. **How is knowledge-base isolation enforced in retrieval?** Short: SQL filters the KB before ordering and limiting results. Deep: Go first checks membership; Python's Agent tools recheck membership and document scope. A filter after Top-K could both leak and displace relevant rows. Code: `ai-service/app/rag.py`, `ai-service/app/agent.py`, `backend/internal/httpapi/api.go`.
9. **How are citations guaranteed to refer to real rows?** Short: The model returns only indices into supplied context; the server constructs citation objects from retrieved rows. Deep: Invalid indices are ignored and an answer with no valid reference abstains. This guarantees provenance, not that the passage supports every claim. Code: `ai-service/app/providers.py`, `ai-service/app/rag.py`.
10. **What is citation relevance?** Short: Whether each cited passage supports the answer's fact. Deep: The project separately checks row existence/scope and fixture-specific expected-reference containment; a passage can be real yet irrelevant, and a lexical check is not semantic entailment. Evidence: `docs/evaluation/MANUAL_REVIEW_LOCAL.md`, `docs/FINAL_VALIDATION.md`.
11. **Why did development Provider scores reach 1.00?** Short: Deterministic test providers and a small synthetic fixture make that possible. Deep: Hash vectors and extractive text are not neural semantics; report their results separately from local BGE/Qwen and do not infer real-world quality. Code: `ai-service/app/providers.py`, `docs/RAG_EVALUATION.md`.
12. **What does a complete RAG request do?** Short: Authenticate, embed question, scoped Top-K, rerank, build context, generate answer, map citation indices. Deep: Debug mode records stages and timing but includes text and is meant only for trusted local development. Code: `backend/internal/httpapi/api.go`, `ai-service/app/rag.py`.
13. **What do Hit@K, Recall@K and MRR measure?** Short: Presence, fraction and rank of expected retrieved evidence. Deep: Hit@K is binary per question; Recall@K divides expected chunks found by expected chunks; MRR averages reciprocal first relevant rank. They measure retrieval, not answer faithfulness. Code: `ai-service/app/evaluate.py`.
14. **How do you evaluate refusal?** Short: Include questions whose answers are absent from the corpus and check abstention without citations. Deep: Four such fixture questions passed locally, but adversarial and ambiguous cases remain outside this narrow set. Code: `docs/evaluation/cases.json`, `ai-service/app/evaluate.py`.
15. **Why use a PostgreSQL Job Queue?** Short: A document and its job can commit atomically in one database. Deep: Polling and leases are sufficient for current scale; Kafka would add operational complexity without a measured need for cross-service event streaming. Code: `backend/internal/jobs/worker.go`, `docs/ASYNC_JOBS.md`.
16. **How does `FOR UPDATE SKIP LOCKED` work?** Short: A worker locks an eligible job row and other workers skip it. Deep: The claim transaction is short; no lock is held through model inference. This prevents simultaneous claims at that point, but crash recovery still means at-least-once execution. Code: `backend/internal/jobs/worker.go`.
17. **How are failed jobs retried?** Short: Up to three attempts with bounded delays, then terminal failure. Deep: The job stores attempts, last error, timestamps and lease; an expired processing lease is reclaimable after restart. Code: `backend/internal/jobs/worker.go`, `backend/migrations/0004_processing_jobs.sql`.
18. **Can two workers write duplicate chunks?** Short: Final stored chunks are idempotent. Deep: A per-document advisory lock serializes processing, chunk replacement is transactional, and `(document_id,chunk_index)` is unique. External embedding work can still repeat after a crash. Code: `ai-service/app/rag.py`, `backend/migrations/`, `docs/ASYNC_JOBS.md`.
19. **Why is upload HTTP 202?** Short: The server accepted a durable job, not finished indexing. Deep: Clients poll document state; `ready` indicates usable vectors, while failed work exposes a reason. Code: `backend/internal/httpapi/api.go`, `docs/ASYNC_JOBS.md`.
20. **Why not claim exactly-once jobs?** Short: A crash can occur after processing but before recording completion. Deep: Leases enable replay, and idempotent database writes make repeat execution safe for stored state; repeated provider calls remain possible. Code: `backend/internal/jobs/worker.go`, `ai-service/app/rag.py`.
21. **Where is RBAC enforced?** Short: In Go routes and again at Python Agent tool execution. Deep: Hiding a frontend button is irrelevant to direct HTTP requests; tests changed URLs and roles to prove server denial. Code: `backend/internal/httpapi/api.go`, `ai-service/app/agent.py`, `docs/RBAC.md`.
22. **What roles exist?** Short: Admin manages the KB and members; editor manages documents; viewer reads and asks. Deep: Any authenticated user can create a new KB and becomes its admin; this bootstrap policy is suitable only for the current prototype. Code: `backend/migrations/0005_auth_rbac.sql`, `docs/RBAC.md`.
23. **How are passwords and sessions protected?** Short: bcrypt stores hashes; signed JWTs identify users. Deep: Token expiry, issuer and audience are checked, secrets stay out of Git; email verification, rate limiting and revocation are not implemented. Code: `backend/internal/httpapi/auth.go`, `docs/SECURITY.md`.
24. **Why is prompt isolation insufficient by itself?** Short: A model may still follow hostile document text. Deep: The real boundary is a tool allowlist, strict schema, parameterized SQL, and DB permission checks independent of model output. Eight invalid plans were tested; this is not a complete security proof. Code: `ai-service/app/agent.py`, `docs/SECURITY.md`.
25. **Which Agent tools can run?** Short: `search_knowledge_base` and `get_document_metadata`, both read-only. Deep: Unknown names, extra fields, cross-KB IDs and invalid UUIDs are rejected before execution; no shell, URL fetch or generated SQL exists. Code: `ai-service/app/agent.py`, `docs/AGENT_DESIGN.md`.
26. **Why JSON planner rather than native function calling?** Short: The local Qwen path was verified using JSON planning over an OpenAI-compatible endpoint. Deep: The planner is interface-based, but its output is untrusted and validated; do not advertise this as native tool calling. Code: `ai-service/app/agent.py`.
27. **What is one Agent request's data flow?** Short: Go authenticates, Qwen plans, Python validates and executes at most one tool, then Qwen answers with server-owned citations. Deep: The tool rechecks membership and logs only name, request ID, duration and outcome. Code: `backend/internal/httpapi/api.go`, `ai-service/app/agent.py`.
28. **How do you avoid model-generated SQL?** Short: There is no SQL tool; queries are fixed and parameterized in code. Deep: The planner can only fill validated values in two schemas. Even a prompt that asks for SQL cannot expand the tool allowlist. Code: `ai-service/app/agent.py`.
29. **Why is real-model latency above test Provider latency?** Short: BGE and Qwen perform actual inference, while hash/extractive stubs do not. Deep: Warm and cold runs, GPU contention, output length and planner calls differ; sequential local measurements are not capacity benchmarks. Evidence: `docs/RAG_EVALUATION.md`, `docs/FINAL_VALIDATION.md`.
30. **What did the “30” answer failure reveal?** Short: Correct retrieval and citation do not guarantee a self-contained answer. Deep: The source contained “30 minutes”; the LLM omitted the unit. A general unit/condition instruction and a live regression case address this without hardcoding the fact. Code: `ai-service/app/providers.py`, `ai-service/tests/test_providers.py`.
31. **How do model changes affect pgvector?** Short: Dimensions and model identity must match stored vectors. Deep: Even equal dimensions do not make vector spaces interchangeable. The staged reindex builds a separate set and switches atomically after checks. Code: `ai-service/app/reindex.py`, `docs/REINDEX.md`.
32. **What are the three largest current limits?** Short: Narrow synthetic evaluation, no production auth hardening, no sustained scale proof. Deep: Other limitations include single-host Compose, lexical rerank and JSON planner; propose broader independently annotated cases, security controls and measured deployment tests before claims. Evidence: `README.md`, `docs/FINAL_VALIDATION.md`.
